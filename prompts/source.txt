A data center network for machine learning is built differently from one for web traffic. A web request is a short conversation between a client and a server, and thousands of independent flows share every link. A backend network for AI is dominated by a few very large flows that run between accelerators for the whole life of a job. Each flow carries tensors, and the tensors are big. When a flow is slow, the accelerator at the other end sits idle, and an idle accelerator is the most expensive thing in the building.

The standard topology for this fabric is a Clos network. Servers connect to leaf switches. Every leaf connects to every spine. Traffic between two servers on different leaves crosses exactly one spine, so every path has the same length, and the number of equal cost paths is the number of spines. Routing uses a simple underlay, often eBGP with one autonomous system per leaf and a shared autonomous system for the spines. Each switch installs several next hops for a remote prefix and spreads flows over them. This is equal cost multipath, or ECMP.

ECMP chooses a path by hashing header fields, usually the source and destination addresses, the protocol, and the transport ports. All the packets of one flow hash to the same path, which keeps them in order. This works well when there are many flows, because the law of large numbers evens out the load. It works badly when there are few flows. Two large flows have a fair chance of landing on the same spine while another spine is idle. The hash has low entropy, and the fabric looks congested even though total capacity is plentiful.

RDMA over Converged Ethernet, version two, carries remote direct memory access inside UDP packets. The destination port is 4791. The source port is chosen by the sender and is often derived from the queue pair number, so it provides the entropy that ECMP needs. Behind the UDP header sits the InfiniBand base transport header, which names the destination queue pair and a packet sequence number. For an RDMA write, the first packet also carries an extended header with the remote virtual address, the remote key, and the total length of the message. The payload follows, and an invariant checksum closes the packet.

A reliable connection queue pair expects packets in order. If one packet is lost, the receiver notices a gap in the sequence numbers and asks the sender to start again from the gap. This is go back N retransmission. It is simple to implement in hardware, but it makes loss expensive, because one lost packet causes everything after it to be sent twice. Production RoCE fabrics therefore try hard not to lose packets. They mark packets with explicit congestion notification before queues overflow, they let the receiver ask the sender to slow down with congestion notification packets, and some also use priority flow control to pause a link before a buffer fills.

Large language model inference has two phases that stress a machine in different ways. The first phase, called prefill, reads the whole prompt at once. Every prompt token is processed in parallel, which keeps the matrix units busy, so prefill is limited by compute. While it runs, each attention layer computes a key vector and a value vector for every prompt token and stores them. That store is the key value cache. The second phase, called decode, produces the answer one token at a time. Each step reads the entire cache and the model weights to produce a single new token, and it appends one new key and value to the cache. Decode is limited by memory bandwidth and by the latency of each step.

Because the two phases want different things, operators have started to run them on different machines. A prefill pool is sized for compute and a decode pool is sized for memory bandwidth, and each can be scaled independently. A long prompt arriving on the prefill pool no longer stalls the streaming answers of other users on the decode pool. The price is that the cache created by prefill must now travel to the machine that will run decode. The cache can be hundreds of megabytes for a long prompt on a large model, and the user is waiting, so the transfer sits directly on the path to the first token.

The transfer is usually a push or a pull between registered memory regions. The decode side allocates and registers a buffer, and tells the prefill side its address and remote key. The prefill side then issues RDMA writes into that buffer, and the final write carries an immediate value that tells the decode side the data is complete. The switches in between know nothing about attention or tensors. They see UDP packets with a DSCP value, they hash the headers, they queue the packets, and they forward them. The quality of the answer cannot depend on the network, but the time to the first token certainly can.

Operators measure the cost of this handoff in several ways. The first is the volume of the cache, which grows linearly with the number of prompt tokens, the number of layers, the number of key value heads, the size of each head, and the number of bytes used for each stored number. Grouped query attention reduces the number of key value heads, and storing the cache in a narrower number format halves its size again. The second is the time spent waiting for the network, which depends on the bandwidth that one flow can actually obtain, not on the bandwidth printed on the port. A flow that is hashed onto a busy spine, or that suffers loss and must retransmit, sees only a fraction of the line rate. The third is how much of the transfer can be hidden behind computation. If the prefill machine sends each layer as soon as that layer is finished, the network works while the processors continue with the next layer, and only the tail of the transfer is exposed to the user.

None of these costs can be seen from inside the model. They appear in the counters of the switches, in the retransmission statistics of the network cards, and in the timestamps of the packets. That is why a lab that moves a real cache between two real processes across a real routed fabric is useful. It lets an engineer change one variable at a time, such as the prompt length, the number of queue pairs, the sending rate, or the delay between the leaves, and watch what happens to the first token. It also gives a way to check, with a byte checksum and a comparison of the generated tokens, that the answer produced after the handoff is exactly the answer that would have been produced without it.

Finally, there is the matter of failure. Links go down, optics fail, and switches reboot. A reliable connection will time out and retransmit, and as long as another path exists the transfer will complete, but the request that was in flight will see a stall. A good test of any fabric designed for inference is to remove a spine link in the middle of a transfer and measure how long the user waits, and whether the tokens that follow are still correct.
